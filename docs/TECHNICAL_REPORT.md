# CSS PHY Transmitter — Technical Report

## 1. Scope

This repository implements a synthesizable IEEE 802.15.4 Chirp Spread Spectrum PHY transmitter following the supplied course assignment and MATLAB reference/fixed-point behavior. The public repository intentionally does not republish the supplied PDF/DOCX/ZIP course files; it contains the implementation, reproducible models, tests, minimal numerical source vectors and EDA preparation.

## 2. Supported modes

- 1 Mbps CSS mode
- 250 kbps CSS mode
- payload length 0..127 bytes
- four chirp indices m=1..4
- 32 MHz reference sample cadence, with integer `SAMPLE_DIV` support for higher system clocks

## 3. Transmitter processing chain

```text
Payload RAM
→ PHR
→ MATLAB-exact zero padding
→ I/Q DEMUX
→ bi-orthogonal symbol mapping
→ 250-kbps interleaver / 1-Mbps bypass
→ preamble + SFD + coded data PPDU
→ QPSK
→ DQPSK with four-symbol feedback
→ CSK using fixed chirp ROM
→ signed 8-bit Tx_real / Tx_imag
```

The design is separated into datapath/control modules rather than one monolithic FSM.

## 4. PPDU and bit ordering

The implementation preserves the supplied model's ordering conventions: payload bytes are serialized LSB-first, PHR payload-length bits 0..6 are transmitted first, the first serial bit after framing goes to I and the second to Q, the first bit collected for a mapper symbol is the symbol-address MSB, and mapper codeword c0 is transmitted first. The 250-kbps path applies the exact documented 64-chip group permutation.

Directed asymmetric bytes `01`, `80`, `96`, `A5` and `3C` are used to catch reversal errors.

## 5. QPSK and DQPSK

`qpsk_mapper.sv` implements the exact four-point orientation used by the reference equation. `dqpsk_encoder.sv` maintains four feedback phases implementing `S[n]=X[n]·S[n-4]`. The supplied fixed-point path initializes the feedback values to unnormalized `1+j`; the RTL preserves that behavior instead of introducing a normalization not present in the reference.

## 6. Chirp generation and CSK

Runtime sine/cosine functions are not used in synthesizable RTL. Four chirp sequences are generated reproducibly and stored as signed 6-bit ROM samples. Each chirp comprises four 38-sample subchirps (152 active samples), followed by the required even/odd gap. The gap table is:

| m | even gap | odd gap |
|---:|---:|---:|
| 1 | 10 | 70 |
| 2 | 20 | 60 |
| 3 | 30 | 50 |
| 4 | 40 | 40 |

Gap samples are explicit zeros. The CSK modulator includes one-group look-ahead buffering so the implementation does not create extra bubbles between groups.

## 7. Fixed-point design

The supplied fixed-point model uses signed six-bit chirp quantization with `floor` semantics. The RTL uses integer arithmetic throughout the synthesizable datapath.

Key formats:

| Stage | Format |
|---|---|
| mapped chip | exact logical sign |
| QPSK real/imag | signed 3-bit integer |
| DQPSK feedback | signed 3-bit integer |
| chirp ROM real/imag | signed 6-bit integer |
| CSK multiply partial | signed 9-bit integer |
| CSK add/sub result | signed 10-bit integer |
| final output | signed 8-bit integer |

The generated/reference range checks establish that final values fit the signed 8-bit interface for the verified cases.

## 8. MSE

The normalized chirp MSE is regenerated by `matlab/mse/mse_analysis.py`. For the supplied six-bit `floor` behavior:

```text
MSE = 0.000891330083552
requirement: MSE < 0.005
```

The numerical reconstruction also matches the supplied m=1 fixed-point sample vectors exactly for all 152 real and 152 imaginary active samples.

## 9. Verification architecture

The project contains two complementary layers:

1. Python source/reference/architecture regression, including exact source-vector comparisons, full-chain integer reconstruction, bit-order tests, randomized deterministic tests and EDA-report parser tests.
2. Self-checking SystemVerilog unit/integration testbenches executed by Icarus Verilog when available.

Before public publication, the tool-independent suite executed 46 Python tests with zero failures. The public GitHub workflow installs Icarus Verilog and Verilator and runs the same top-level verification driver so HDL compile/simulation/lint results come from actual tool execution.

Required integration matrix:

```text
1 Mbps:   0, 1, 3, 25, 127 bytes
250 kbps: 0, 1, 3, 25, 127 bytes
```

Each top-level test compares every emitted real/imaginary sample with deterministic golden data.

## 10. Synthesis and timing

The Vivado flow is target-safe: `FPGA_PART` must be explicitly supplied. The XDC contains only configurable timing until board pins/I/O standards are known. The flow generates synthesis and implementation utilization/timing/methodology reports and refuses to treat timing as valid without a real `sys_clk` constraint.

No LUT/FF/BRAM/DSP, WNS/TNS, Fmax, power, bitstream or board result is reported without real tool evidence.

## 11. Reproducibility

Primary commands:

```bash
make verify
make rtl
make lint
python3 matlab/mse/mse_analysis.py
```

Vivado, after a real target is selected:

```bash
FPGA_PART=<part> CLOCK_PERIOD_NS=31.250 vivado -mode batch -source scripts/vivado_synth.tcl
FPGA_PART=<part> vivado -mode batch -source scripts/vivado_impl.tcl
```

## 12. Remaining target-dependent work

Full assignment completion still requires real HDL CI/local simulator evidence, real lint evidence, selection of an exact FPGA part/board, synthesis/place-and-route/timing evidence, board constraints, bitstream generation and on-board verification. These stages are deliberately not fabricated.
